# 自動記録・AR吹き出し 0.4.0

更新日：2026-09-13

## 変更内容

- H01〜H08を約0.45秒連続して認識すると、その端末の捜査メモへ一度だけ自動記録する。
- 一瞬映っただけのカードや、安定する前に見失ったカードは記録しない。
- 同じカードを再び読んでも重複記録しない。
- おばけの上に、話者名とMissionのヒント文を表示するAR吹き出しを追加した。
- 自動記録時に短い2音、正解時に短い3音を鳴らす。音を開始できない環境でも進行は止めない。
- 0.3.0のMission IDとMission版を維持し、既存の9枚版メモを0.4.0でも引き継ぐ。

## AR吹き出しの方式

吹き出しはカメラ画面内の固定位置ではない。マーカーに追従するおばけ上部の3D座標を毎フレーム画面座標へ投影し、その位置へ読みやすいHTMLの吹き出しを重ねる。マーカーを動かすと吹き出しも追従し、見失うと消える。

日本語を3Dテクスチャへ焼き込む方式より文字を鮮明に保ち、8枚分の大きなテクスチャを常駐させないため、iPad Air 2のメモリ負荷を抑えられる。吹き出しの位置は画面端で制限し、本文が画面外へ切れにくいようにした。

検証画面の1枚・4枚・9枚認識ではMissionを渡さないため、従来どおり吹き出しを表示しない。ゲーム画面だけがMissionのセリフを読み込む。

## PCでの確認

- TypeScriptの型チェックとproduction buildに成功。
- Vitest 91項目に合格。
- 開発用認識で、0.15秒の短い認識は保存せず、安定認識で自動保存することを確認。
- 4枚版と9枚版で、自動記録、重複防止、途中保存、相談、ANSWER、正解、リセットを確認。
- production buildへ合成カメラ映像を入力し、実際のMindARでH01〜H08を順に認識。各AR吹き出しの話者名・本文がMissionと一致し、全ヒントが自動保存された。
- ANSWERから正解まで進み、検証画面のカメラ開始・停止と権限拒否時の復帰案内も維持。

Chromium・SwiftShader・合成映像による確認であり、Air 2の表示位置、文字サイズ、音量、処理速度を保証するものではない。

## iPadで確認する項目

1. Safariで再読み込みし、画面下部が0.4.0になっていることを確認する。
2. H01を一瞬だけ映してすぐ外し、メモが増えないことを確認する。
3. H01をおばけと吹き出しが出るまで映し、ボタン操作なしで「1 / 8」になることを確認する。
4. カードをゆっくり動かし、吹き出しがおばけと一緒に動くこと、文字が画面外へ切れないことを確認する。
5. H01〜H08を続けて読み、各セリフ・記録音・8つの取得欄を確認する。
6. ANSWERから「あお・ぼうし」を選び、正解音まで確認する。

吹き出しが大きすぎる、小さすぎる、おばけを隠しすぎる、動きが気になる場合は、見え方が分かるスクリーンショットと端末の向きを記録する。音が不要または大きすぎる場合も、会場運用に合わせて調整する。
