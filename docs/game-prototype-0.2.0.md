# 4枚で遊ぶゲーム試作（0.2.0）

## 入口と遊び方

トップページをゲーム画面にした。従来の検証画面は `lab.html` に移動し、ゲームのフッターから開ける。カメラ開始、MindAR、静止保持、GLB、印刷物、認識データは引き継ぐ。

1. Safariでトップページを開き、「たんけんを はじめる」を押す。
2. 印刷済みH01・H02・H03を読む。450ms以上認識が続くと、画面におばけのセリフが出る。
3. 「ヒントを記録する」で、そのiPadのメモへ保存する。記録前にカードを見失うとセリフは消える。記録後のメモは残る。
4. 「みんなと そうだんする」でメモを見せ合う。全ヒントを集めていなくても進める。
5. 代表者が「回答マーカーを読む」を押し、ANSWERを読む。
6. 色 → アイテム → 確認の順に答える。誤答なら相談・再回答へ戻れる。回数制限なし。
7. 正解画面をスタッフへ見せ、現実のボールでのおばけ退治へ進む。

試作用の答えは青い帽子。条件は実装計画どおり、H01は赤と眼鏡を除外、H02は黄色とネクタイを除外、H03は紫とリボンを除外する。本番の協力バランスを検証した問題ではない。

## ゲームとAR

Missionは `public/missions/prototype.json`。読み込み時に選択肢、ID重複、マーカー番号とセットの対応、素材の版、正解との整合、全ヒントでの一意性を検証する。ヒントの表示文と条件は別データ。

条件は肯定・否定・AND・ORを扱い、色×種類の組み合わせ全体で評価する。メモの○は全候補で共通、×は全候補から除外、？はそのどちらでもないことを示す。複合条件でも各軸だけに分解して誤推理しない。取得したセリフもメモに保持する。

探索中にANSWERを読んでも回答画面へ移らず、相談を案内する。回答用スキャンではヒントのカードを読んでも回答できない。認識の連続通知では同じカードの待機時間を再設定せず、別のカード・喪失・停止時には待機を消す。記録ボタンの操作時にも、そのカードがまだ認識されていることを確認する。

ゲーム用カメラは960×720を要求し、0.1.5の静止保持と静止モデルを使う。実際の映像寸法は端末による。メモ・相談・回答・正解・ホームへ移るとiframeを破棄する。バックグラウンドでも停止し、戻った際はボタンで再開する。Safariのタップ再生と開始中断時の回復処理は既存のARフレームを使用する。

## 保存

`ar-obake-game-v1` にschemaVersion・missionId・missionVersion・取得markerId・進行区分・直近20回の回答を保存する。推理結果は取得IDから再計算する。AR姿勢や映像は保存しない。端末間の同期は実装せず、人同士で情報を共有する。

読み込み時には未知ID・重複・不正な完了状態・異なるMissionを検出し、元データを自動で上書きしない。利用者が確認画面で新規開始した場合にだけゲームの保存を置き換える。保存不可・容量不足では注意を表示し、その場のプレイは継続する。検証用 `ar-obake-lab-v1` は別キーなのでリセットで消えない。

## 開発・検証

開発サーバーだけで `/?simulate=1` を開くと、認識を再現する操作部が出る。本番ビルドでは処理と操作部を削除し、同じクエリを付けても通常カメラになる。

- `tests/game.test.ts`：ヒント演算、全取得順、重複防止、未知ID、矛盾、Mission検証、正誤判定、再回答、保存復元・破損・容量不足、端末分離、認識待機と喪失。
- `scripts/game-browser.mjs`：開発用認識を使う画面遷移・メモ・再回答・復元・確認つきリセット・横幅の検証。結果は `game-browser-results.json`。
- `scripts/game-real-ar.mjs`：配信用ビルドに合成映像を入力し、実際のMindARで3ヒント取得→メモ・相談→ANSWER→正解を通す。開発機能の無効化、既存検証画面、カメラ拒否からの再開操作も確認。結果は `game-real-ar-results.json`。

型チェックと単体79項目に合格。ブラウザ試験の具体的結果は各JSONに記録する。合成カメラとSwiftShaderの速度はAir 2の性能を表さない。
