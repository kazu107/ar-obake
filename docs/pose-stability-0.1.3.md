# 小刻みな追従の揺れへの対応（0.1.3）

## 今回の実機結果

利用者の0.1.2の記録では、1枚 / 960 × 720 / stable / stillで148.2秒動作し、平均描画26.7fps、最低21.5fps。カメラ開始と認識には成功し、ユーザー停止で終了したが、小刻みな揺れが続いたとの報告。

前回の安定化設定と静止モードは実際にiframeへ届いていた。設定の反映漏れや意図的なふわふわでは説明できない。旧ログには位置・回転の数値がなく、原因と揺れの大きさは断定できない。提供された生ログはリポジトリに含めない。

配信に使うMindAR 1.2.5のdist/controller-mGt1s8dJ.jsも調査し、filterMinCF/filterBetaがフィルターへ渡り、フィルター後の行列がonUpdateへ渡されることを確認した。アプリはそれを認識更新のたびにそのまま差し替えていた。

## 変更

- stableモードでは、MindARの反応の速い既定設定から受けた行列をマーカー中心へ変換してから、位置とQuaternion回転に分ける。
- 位置はマーカー幅の0.4%、回転は2度のsoft deadbandを設ける。前回の入力ではなく保持中の目標との差で判断するため、ゆっくりした移動も追従する。
- 描画の経過時間に基づき位置をlerp、回転をslerpで補間する。通常の時定数は位置100ms、回転160ms。大きい移動では速く追いつく。
- 出力を一定のマーカー幅で再構成し、行列要素の補間に由来する非一様な拡大縮小・せん断を表示に持ち込まない。
- 初回認識と見失った後の再認識は新しい位置から開始する。別マーカーごとに状態を独立させる。
- 「前回の安定化（0.1.2）」はlegacyモードとして保持。「従来の追従」は最初の既定設定。新方式は「揺れを抑える（改良）」が初期値。

平面の姿勢の曖昧さ自体を解決する認識器の変更ではない。小さな実際の移動・回転も許容幅内では抑えられ、速い動きには追従の遅れがある。実機での改善は未確認。

## 10秒間の数値記録

「揺れを10秒記録」を押すと、認識中に最大10Hzで補正前後のアンカー姿勢を記録する。数値のみで映像は保存しない。1回最大110点、1セッション最大3回、従来どおり直近10セッションを保存する。

- input: アプリの新しい補正に入る直前のMindAR出力。MindAR内部フィルターより前の生推定ではない。
- displayed: 実際に描画したアンカー姿勢。モデル自身のアニメーションは含まないので、比較時は静止にする。
- 各配列は位置x/y/z（マーカー幅単位）とQuaternion x/y/z/w。
- atMsは記録開始からの描画時刻、inputAtMsは最後のMindAR通知時刻（開始前は0）、updateIndexはそのマーカーの通知連番。
- 見失っている間は点を追加しない。停止時には途中までをcancelledとして保持する。

カードとiPadを支えて正面で10秒静止し、JSONを書き出す。新方式でも残る場合は補正前後と通知間隔を比較して追加調整する。必要なら同じ解像度・距離でlegacyも記録する。

## 検証

単体38項目：小変動の保持、ゆっくりした移動、描画間の補間、フレーム頻度によらない経過時間、動いた後の追従、喪失後の初期化、剛体スケール、無効入力、記録上限と値検証に加え、既存の開始復帰・計測・旧フィルターの試験。

ブラウザーではproduction buildと実際のMindARで全セットを確認し、10秒記録の完了・中止・JSONへの保存を検証する。結果はbrowser-test-results.jsonとbrowser-error-test-results.json。合成映像の試験をiPadの揺れ改善の証拠としては扱わない。
