# 9枚ミッション 0.3.0

更新日：2026-09-12

## 変更内容

トップページを「8にんの おばけのひみつ」（H01〜H08＋ANSWER）に切り替えた。捜査メモには8つの取得欄を追加し、記録ずみ・未取得を番号と記号で区別する。既存の印刷物9枚、認識データ、GLB、受け入れ済みの静止保持を継続する。

4枚の試作は `/?mission=practice` で利用できる。9枚版は `ar-obake-game-v1:obake-mission-01`、4枚版は従来の `ar-obake-game-v1`、検証記録は `ar-obake-lab-v1` に保存する。片方のリセットで他方を消さない。Missionの版が合わない保存は、確認なしに流用しない。

Mission IDは `obake-mission-01`、版は1、素材版は `calibration-v1`。既存の4枚版と同じ仮の正解「あおい ぼうし」を使う。現実のおばけが身に付ける最終アイテムとの一致は、本番準備で確定する。

色4種 × アイテム4種の16候補を条件で絞る。画面のセリフと条件データを別に持ち、テストで両者の意味を検証する。

| マーカー | targetIndex | 条件 |
| --- | --- | --- |
| H01 | 0 | 青または紫 |
| H02 | 1 | 帽子またはリボン |
| H03 | 2 | 黄ではない |
| H04 | 3 | ネクタイではない |
| H05 | 4 | 青または黄 |

| H07 | 6 | 赤ではない、かつリボンではない |
| H08 | 7 | 紫ではない、かつ眼鏡ではない |
| ANSWER | 8 | 相談後の回答を開く |

## 全256通りの検証

実装と同じMissionパーサー・条件演算を使って、取得するヒントの全部分集合を列挙した。取得順序と重複は結果に影響しない。正解がすべての集合に残り、全8枚では「あおい ぼうし」だけになる。

| 異なるヒントの枚数 | 答えが一意になる組み合わせ | 割合 |
| --- | --- | --- |
| 0 | 0 / 1 | 0% |
| 1 | 0 / 8 | 0% |
| 2 | 0 / 28 | 0% |
| 3 | 0 / 56 | 0% |
| 4 | 12 / 70 | 約17% |
| 5 | 30 / 56 | 約54% |
| 6 | 24 / 28 | 約86% |
| 7 | 8 / 8 | 100% |
| 8 | 1 / 1 | 100% |

最小必要枚数は4枚。1〜3枚だけでは色と種類の両方を確定できない。どの1枚を取り逃しても、残り7枚で答えが決まる。6枚の組み合わせの80%以上で解ける初期目標も満たす。これは論理的に答えが決まる割合であり、子どもの正答率や所要時間を測った値ではない。

6枚を集めても決まらないのは、次の2枚を同時に取り逃した場合。どちらか1枚を補えば確定する。

| 取り逃した2枚 | 正解以外に残る候補 |
| --- | --- |
| H01・H03 | 黄色い帽子 |
| H02・H04 | 青いネクタイ |
| H05・H08 | 紫の帽子 |
| H06・H07 | 青いリボン |

詳細は [mission-balance.json](mission-balance.json) に、全候補列・枚数別集計・包含関係で最小の解決集合を保存した。再生成は `npm run check:mission`。条件未達・矛盾・全体の不成立があると終了コード1になる。

## スタッフの進め方

- 探索場所を分担し、1人1〜3枚程度の異なるヒントを集めるよう案内する。
- 相談では、重複を除いて合計6〜7枚のヒントを目安に持ち寄る。確実に絞れるようにする場合は7枚にする。
- 上の4組は、2枚とも同じ場所で見落とさないよう別の探索場所へ分ける。分からない場合は未取得のカードを1枚追加する。
- 各端末は自分のメモだけを表示する。友達の情報は自動合算されないため、セリフと候補を見せ合い、代表者が相談した答えを選ぶ。

1人が多数のカードを読める設計なので、協力をシステムで強制するものではない。全ヒントを読まなくてもANSWERへ進める。問題を知っている場合や推測による正解も可能。
