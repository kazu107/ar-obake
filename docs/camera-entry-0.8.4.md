# 0.8.4 カメラからの開始と設定メニュー

公開URLを開くとタイトル・開始ボタンを挟まず、保存した進捗に応じた画面を開く。カメラ画面ならその場でカメラの準備を開始する。初期読み込み中もヘッダーとタイトルは表示しない。

| この端末の進捗 | 最初の画面 |
| --- | --- |
| 初回・TUTORIAL未完了 | TUTORIALのカメラ |
| 探索中・TUTORIAL完了 | メモを復元した探索カメラ |
| 相談中 | ANSWERのカメラ。相談画面にも戻れる |
| 正解済み | 保存した正解画面。「もういちど あそぶ」からリセット |
| 保存内容が破損・別バージョン | カメラ画面の確認案内。許可を要求せず、保存内容も上書きしない |

4枚版も直接探索カメラへ入る。チュートリアルのない試作なのでTUTORIALは挟まない。進捗は10枚版と別に保存する。

カメラの左上に歯車を表示する。押すとプルダウンが開き、次の操作を選べる。利用者に見える文言はひらがな。

- 「たいとるへ もどる」：従来のタイトル画面へ移動する。`/?title=1`を直接開くこともでき、そこで自動的にカメラは開始しない。
- 「しんちょくを りせっと」：確認画面を開く。確定するとこのミッションのメモ・回答・TUTORIAL完了を消し、TUTORIALのカメラから再開する。取り消すと進捗を保持して元のカメラへ戻る。マーカーごとの角度設定と、もう一方のミッションは保持する。
- 「すたっふの がめん」：従来のスタッフURLへ移動する。オフライン準備・角度設定・資料は引き続きここで操作する。

プルダウンの開閉でカメラを停止しない。外側やAR映像のタップ、Escapeで閉じられる。タイトル・スタッフへの移動とリセットの確認中にはカメラを停止する。

## カメラ許可とSafari

初回の許可画面はブラウザの機能なので、利用者が許可する必要がある。Safariが動画の自動再生を止めた場合は、同じカメラ画面内の「かめらを うつす」を押す。許可拒否・バックグラウンドからの復帰などは既存の再開ボタンを使う。ブラウザの全画面表示にも端末側の制約があるため、Safariの枠を隠す運用は「ホーム画面に追加」を使う。

## 更新とiPadでの確認

1. 通信できる状態で`/?staff=1`を開き、アプリ0.8.4を確認してオフラインデータを更新する。
2. ゲームのURLを開き、タイトルを挟まずカメラ画面になり、許可後に映像が出ることを確認する。初回に戻す場合は歯車からリセットを確定する。
3. TUTORIAL→H01の自動記録を確認する。再読み込み後は探索カメラとH01のメモが復元される。
4. 歯車からタイトルへ移動し、続きからカメラへ戻る。リセットの取り消し・確定も確認する。
5. Wi-Fiは実際のカメラ映像が出てから切る。完全オフライン状態からカメラを新規起動する試験は、通信切断後の継続動作とは分ける。

Mission v2・マーカー画像・認識データ・印刷PDFは変更していない。既存の0.8.0以降のカードをそのまま使える。

## 検証

型チェック、単体テスト128項目、配信用ビルドに合格した。初回・進捗復元・リセット・再生拒否からの復帰、実際のMindARで全10枚から正解まで、準備後のオフライン読み込みを確認し、ブラウザの未処理エラーは0件だった。結果は次のファイルに記録した。

- `camera-entry-browser-results.json`：初回・途中・相談中・正解済みの入口、設定メニュー、リセット、保存破損・保存不可、明示的なタイトル・スタッフ入口。
- `nine-game-browser-results.json`：従来のタイトルからの開始、メモ・相談・回答・復元・角度設定。
- `nine-game-real-ar-results.json`：配信用ビルドの自動カメラ開始、実際のMindARで全10枚の認識と正解まで、AR映像上の設定メニュー、許可拒否時の再開案内。
- `camera-playback-browser-results.json`：Safariの再生拒否を注入し、同じカメラ画面内のボタンから許可を取り直さずに映像とMindARを開始できること。
- `offline-browser-results.json`：準備済みデータでゲーム・スタッフ画面・ARの必要ファイルを通信なしで開けること。

PCのChromiumと合成映像による確認は、印刷物・iPadのカメラ・Safariでの受け入れ確認とは別に扱う。
