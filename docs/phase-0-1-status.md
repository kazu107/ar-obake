## 実機で観測した問題

0.1.0はAir 2で8回ともカメラ開始中に停止。カメラを許可済みにしても改善しなかった。0.1.1で映像準備待ち・再試行・直接タップ再生・開始段階のログを追加した。0.1.1でカメラ起動とH01認識・おばけ表示の実機成功を確認済み。詳細は[camera-startup-0.1.1.md](camera-startup-0.1.1.md)。

0.1.1の実機記録：640×480で66.2秒、平均描画37.3fps。960×720で149.2秒、平均25.8fps、読取計測1回は2.308秒。両方とも正常なユーザー停止。960側には極端に低い描画サンプルもあり、安定性の合格判定はまだ行わない。正面のモデル揺れが報告され、0.1.2で比較用の安定化設定と静止モードを追加。

0.1.2でもstable＋stillの小刻みな揺れが残ると報告。0.1.3で位置・回転の補正と描画補間を追加し、10秒の数値記録を実装。詳細は[pose-stability-0.1.3.md](pose-stability-0.1.3.md)。

0.1.3でも手持ちの正面の揺れが残ると報告。80点の姿勢記録で回転の抑制と残る奥行き変動を確認し、0.1.4で投影中心・奥行きを分離。集計と比較は[depth-stability-0.1.4.md](depth-stability-0.1.4.md)。

- Node.js 24.19.0、Vite 7.3.6で型チェックとproduction build成功。
- Vitestで48項目（従来38項目と、投影中心・奥行き補正10項目）の検証に合格。

- 権限拒否、認識データのHTTP 503、10秒の未検出、バックグラウンド通知の処理を自動確認。
- 再生のAbortErrorを注入し、自動再試行でAR起動を確認。再生のNotAllowedErrorを注入し、直接ボタン操作からAR起動を確認。ボタン待ちの停止も確認。
