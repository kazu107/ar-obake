# 奥行きを分離した追従補正（0.1.4）

## 今回の観測

0.1.3の960 × 720 / stable / stillで、10秒間・80点の数値記録を受領。利用者は「マーカー固定、iPad手持ち」と回答した。補正前後の回転変動は大きく減っているが、奥行きの変動と、表示の小刻みな揺れが残っていた。

冒頭2秒を除いた隣接記録点間の平均角度変化は入力3.26度、表示0.39度。対数奥行き差の平均は入力1.484%、表示0.435%。認識通知は連番から約23回/秒、記録自体は約8点/秒。記録間には保存されていない認識更新がある。

手持ちの実際の視点移動も含むため、全変動をノイズと解釈できない。奥行きが見かけの大きさへ影響し、位置を強く平滑化するとカードの映像から表示が遅れる可能性を、今回の修正対象とする。実機の真のマーカー姿勢は測れていないので、単独の原因確定や解消宣言はしない。

## 新しい方式

入力のマーカー中心(x,y,z)を、画面上の中心(x/-z,y/-z)とlog(-z)へ分ける。中心位置は45msの時定数で追従し、奥行きは420msで小変動を抑える。対数奥行きの許容幅は約1%、回転は2.5度・240ms。大きな変化には応答を速める。補正した奥行きからX/Yを再構成し、奥行きの揺れが中心位置へ混ざらないようにする。

初回・再認識は現在位置へ配置する。0.1.3をprevious、0.1.2をlegacyとして比較できる。補正方式と定数は既存のtracking設定ログに残す。

## 同じ入力での再生比較

[scripts/replay-pose-recording.mjs](../scripts/replay-pose-recording.mjs)で再現。元ログは指定したローカルファイルから読み、リポジトリには集計結果だけを保存する。

| 指標（冒頭2秒を除く） | 旧方式の再生 | 新方式の再生 |
| --- | ---: | ---: |
| 平均の対数奥行き差 | 0.658% | 0.121% |
| 平均の回転差 | 0.503度 | 0.296度 |
| 入力中心との平均距離 | 3.68px | 3.46px |
| 入力中心との距離の95%点 | 6.67px | 7.21px |

奥行きの平均変動は約81.6%低下した。中心位置の誤差指標は一律には改善していない。pxはMindARの仮想カメラの45度画角と720px高から計算した映像座標で、DOM上のピクセルや真のマーカー位置との誤差ではない。

60Hzで描画し、保存された入力点の間では前の入力を保持する再生。実際の中間更新が欠けているため、旧方式の再生値も実機の表示値と一致しない。新方式の実機効果の保証ではない。詳細は[depth-replay-summary.json](depth-replay-summary.json)。

## 検証

単体48項目。新方式では投影中心の維持、奥行きノイズの抑制、画面上の移動への応答、ゆっくりした移動、接近、描画頻度・マーカー幅の違い、再認識と無効入力を検証。ブラウザーで全マーカー、0.1.3とのモード切り替え、10秒記録、中止・保存を確認する。

実機では同じ960 × 720、静止モードで正面を再試験する。手持ちと台への固定を混ぜずに比較する。近づく・離れる動きの遅れも確認する。
